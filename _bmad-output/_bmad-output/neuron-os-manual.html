1. Executive Overview

What is Neuron OS?

Neuron OS is an autonomous business operating system that learns your business and accelerates everything. It is NOT a chatbot — it's a platform where AI agents work FOR you, executing real business processes with real tools.

Core Differentiators

FeatureTraditional AI ToolsNeuron OS
Starting pointBlank conversationPre-built brain with 445 concepts rewritten for YOUR industry
ExecutionText suggestionsAutonomous agents that call APIs, search databases, score leads
KnowledgeLost after conversationLiving Obsidian vault that compounds with every interaction
SecurityOne-size-fits-allSection-level department filtering
EvolutionStaticSelf-healing agents that detect API changes
MonitoringNoneReal-time dashboards for every operation

Target Users

Solo Founders
Need expert guidance across all business functions without hiring consultants
Business Owners with Teams
Need AI-powered execution with role-based access — marketing sees marketing, finance sees finance
Team Members
Execute campaigns, analyses, and strategic work with AI partner support

4. Feature Deep Dives

4.1 Business Brain (Obsidian Vault)

What It Is

A per-tenant knowledge base containing 445 business concepts rewritten specifically for the customer's business. Follows the Karpathy LLM Wiki pattern with three layers.

Vault Structure

tenant-vault/
  wiki/concepts/          ← USER SEES THIS
    Marketing/
      Uvod u Marketing.md   ← 5000+ words, business-specific
    Finansije/
      Budzet.md
    ...22 categories total

  raw/                    ← HIDDEN (immutable sources)
  skills/                 ← HIDDEN (agent skill definitions)
  instructions/           ← HIDDEN (SOUL.md files)
  index.md               ← HIDDEN (fast concept lookup)
  log.md                 ← HIDDEN (operation log)
  SCHEMA.md              ← HIDDEN (conventions)

Section-Level Department Filtering

Key Innovation: Each H2/H3 section within a concept has a department tag. The backend strips sections the user's role can't see BEFORE sending to the frontend. A Marketing user viewing "Financial Plan" sees only the "Marketing Budget" section — not P&L or Cash Flow.

Concept Note Structure

departmentTags: ["Sales", "Marketing"]

  overview: ["all"]
  sales_strategy: ["Sales"]
  marketing_integration: ["Marketing"]

lastReinforced: "2026-04-12"
tier: "semantic"
---

Message Flow

1
User types message — e.g., "How should I price my new product?"
2
Prompt Enrichment (< 500ms) — Brain index lookup → finds "Odredjivanje Cene" → loads concept content filtered by department → adds business profile + quality standards + role perspective

5. Agent Architecture

OpenClaw Relay (Hetzner 91.98.231.87:3100)

Node.js service managing AI agent execution. Backend POSTs to relay, relay loads SOUL.md, runs MiniMax M2.7, returns results.

Agent Registry

Agent IDPurpose
mainConversational director
lead-discoveryLead search + scoring pipeline
content-creationContent generation pipeline
concept-enricherBusiness concept rewriting (onboarding)
proc-{slug}Per-process agents (dynamically created)
+ 8 department agentsMarketing, Finance, Sales, etc.

Per-Process Agent SOUL.md Contains

  • Agent identity + business context (company, industry, ICP)
  • Step-by-step execution plan with JSON specs
  • MCP gateway curl patterns (exact commands, auth, body format)
  • Self-validation gates per step (JSON valid? Items > 0? No errors?)
  • Self-correction rules (7 error types with specific fixes)
  • Spec drift detection instructions (adapt + report API changes)
  • Hard rules (JSON only, no invented data, self-validate every step)

7. MCP Integration Layer

How MCP Calls Work

1
Agent calls exec curl to MCP gateway: POST /api/v1/mcp/{toolSlug}/{operationId}
2
MCP Gateway loads tool from catalog, loads credentials, builds auth headers
3
Gateway executes HTTP call to external API (Apollo, Notion, etc.)
4
Agent receives response, self-validates, proceeds to next step

MCP Self-Evolution

When an API changes: Agent detects the error → tries alternative field names → succeeds → appends _specDrift to output → backend updates MCP catalog → McpEvolutionService propagates to ALL affected processes → regenerates SOUL.md → redeploys to relay. All future agents automatically use the correct field names.
